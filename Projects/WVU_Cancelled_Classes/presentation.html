How This System Was Built

GROUP WORK — CLASS ASSESSMENTS

Core OOP Foundation

The heart of the system — its object-oriented class structure — was designed and coded by the student group across multiple MIST 352 class assessments and assignments throughout the semester.

  • WeatherDay — the central data model holding all 13 weather attributes per day
  • CancellationRecord — links a date to its weather and cancellation label
  • DecisionEngine — rule-based evaluator built from domain knowledge
  • CancellationPredictor — the trained ML model that computes probability
  • NOAAService — the data-fetching and parsing layer for both NOAA and Open-Meteo
AI-ASSISTED — CLAUDE CODE

Extended Functionality via Claude Code

Claude Code (Anthropic's AI coding assistant) was used to bring the main idea to life and build out the full feature set of the application on top of the group's OOP foundation.

  • Animated War Room dashboard and all 7 interactive UI views
  • NOAA GHCN-Daily S3 integration and real-time Open-Meteo API calls
  • 7-day forecast display with per-day cancellation risk cards
  • Statistics engine with 5 navigable tabs (charts, correlations, records)
  • Graceful offline fallback covering all 12 months of the year
Collaboration model: Student group provided the OOP architecture, domain knowledge, and class logic. Claude Code translated the system concept into a fully working, feature-rich application.

The Problem We're Solving

The Challenge

  • WVU sits in the Allegheny Mountains — one of the snowiest regions on the East Coast
  • Cancellation decisions affect 30,000+ students and thousands of faculty
  • No transparent, data-driven tool existed to forecast cancellation risk
  • Students and faculty often learn about cancellations with little advance notice

Our Solution

  • Pull real NOAA weather station data for Morgantown (USC00555882)
  • Overlay live Open-Meteo forecasts for today and the next 7 days
  • Match weather patterns against confirmed WVU cancellation history
  • Output a 0–100% cancellation probability with supporting evidence
Core insight: Past cancellations share measurable weather signatures. By learning from those signatures, we can predict future ones.

Data Source 1: NOAA GHCN-Daily

PRIMARY HISTORICAL DATA
  • Source: NOAA Global Historical Climatology Network (GHCN-Daily) via AWS S3 public bucket
  • Station: USC00555882 — Morgantown Lock 4, WV
  • Format: CSV downloaded at runtime — no API key required
  • Coverage: Full year (Jan–Dec), all 13 weather elements per day
  • Unit conversion: All values converted from SI to US customary (°C→°F, mm→in, m/s→mph)

Data Source 2: Open-Meteo API

LIVE & FORECAST DATA
  • Source: Open-Meteo.com — free, no API key, high-accuracy European weather model
  • Coordinates: 39.6295°N, 79.9559°W (Morgantown, WV)
  • Current conditions: Temperature, snowfall, precipitation, wind speed & gusts, WMO weather code
  • 7-day forecast: Daily max/min temps, snowfall totals, wind, precipitation, weather codes
  • WMO code decoding: Translates numeric codes into boolean event flags (fog, ice, thunder, blowing snow, freezing rain)
HOW IT'S USED

Today's Conditions

The live snapshot feeds directly into DecisionEngine and CancellationPredictor to produce the main cancellation probability shown on startup.

7-Day Forecast View

Each forecast day is converted to a WeatherDay object and run through the predictor — giving students a full week of cancellation risk cards at a glance.

Data Source 3: WVU Cancellation History

GROUND-TRUTH LABELS
  • Plain-text file: WVU_canceled_history.txt
  • One date per line in YYYY-MM-DD | Reason format
  • Lines starting with # are ignored — easy commenting
  • Loaded at startup; matched against NOAA historical days
  • Each matched date becomes a positive training example — the predictor learns what weather looked like on real cancellation days
Known confirmed WVU cancellations loaded:
Jan 6, Jan 7, Jan 21 — Winter storms & ice
Feb 12, Feb 13 — Winter Storm Blair
Mar 3 — Late-season snowstorm
WHY THIS MATTERS

The Training Loop

Without this file the predictor has no labelled examples. With it, the model computes the average weather profile of a cancellation day — typical snowfall, minimum temperature, wind gusts, and composite severity score.

Similarity Matching

Today's conditions are compared to that cancellation profile. The closer the match, the higher the probability. More dates = better predictions.

The Rule-Based Decision Engine

The DecisionEngine applies expert-coded meteorological thresholds. Rules fire in priority order — the first match wins:

ConditionThresholdDecision
Heavy Snowfall≥ 6 inchesCANCEL
Ice / Freezing Rain EventWT04 or WT06 flag setCANCEL
Extreme ColdMin Temp ≤ 10°FCANCEL
Snow + Cold Combo≥ 4" snow AND ≤ 28°FCANCEL
Blizzard (gust + snow)Gust ≥ 35 mph AND snow ≥ 2"CANCEL
High Composite ScoreSeverityScore ≥ 45 / 100CANCEL
Moderate Snow2–4 inchesDELAY LIKELY
All other conditions—HOLD / NORMAL
SeverityScore (0–100) is a weighted composite of temperature, snowfall, wind gust, ice/freeze flags, and snow depth — used as a single normalized measure of overall storm danger.

The ML Cancellation Predictor

Training Phase

  • All NOAA days are loaded and labelled: cancelled vs. normal
  • For cancelled days, four averages are computed:
    → Average snowfall
    → Average minimum temperature
    → Average wind gust
    → Average severity score
  • These averages define the "typical cancellation day" profile

Prediction Phase

  • Today's weather is compared to the cancellation profile using similarity ratios (capped at 1.5×)
  • Weighted score: Snow (35%) + Severity (30%) + Temp (20%) + Wind (15%)
  • Scaled by the historical cancellation base rate
  • Bonus: +15% if ice/freeze present; +8% if blowing snow
OUTPUT INTERPRETATION

70–100% → HIGH RISK

Cancellation very likely — monitor WVU alerts immediately

40–69% → MODERATE

Watch WVU communications — delay possible

0–39% → LOW

Classes expected to run normally

Summary & Key Takeaways

Data Integration

  • Three distinct data sources unified into one WeatherDay object
  • NOAA provides the ground truth history; Open-Meteo provides the live edge
  • WVU history file converts raw weather into labelled training data

Decision Making

  • Rule-based engine catches clear-cut extreme cases instantly
  • ML predictor handles nuanced borderline conditions using learned patterns
  • Both models run in parallel — outputs shown side by side

Design Principles

  • No API keys required — fully open data sources
  • Offline fallback covers all 12 months — app is always usable
  • History file is human-editable — users improve accuracy over time
  • All 7 views driven by the same data pipeline — consistent results
Future enhancements: Integrate NWS Winter Storm Watches/Warnings, add multi-year NOAA history for better model training, send push notifications when probability exceeds a threshold.
