How This System Was Built

GROUP WORK — Course Assessments

Core Classes — Built by the Team

The group designed and coded the foundational classes of this system across several assessments throughout MIST 352. These form the backbone of the application:

  • Plant.cs — plant entity with all properties & metadata
  • WeatherDay.cs — daily weather data model
  • GardenEntry.cs — individual planted plot record
  • HistoricalStats.cs — monthly climate aggregates
  • GardenManager.cs — 6×10 garden grid with JSON persistence
  • PlantDatabase.cs — static catalog of 23 plants
  • NOAAService.cs — NOAA & NWS API integration layer
  • Program.cs — application entry point & menu orchestration
CLAUDE CODE — Advanced Features

Features Built on Top — Using Claude Code

Claude Code (Anthropic's AI-powered CLI) was used to implement the advanced feature modules on top of the group's core class foundation:

  • PlantAdvisor.cs — USDA zone calc & seasonal recommendations
  • FrostCalculator.cs — spring/fall frost date analysis
  • CompanionPlanting.cs — plant pairing & conflict detection
  • MoonPhaseCalculator.cs — lunar planting calendar (WOW)
  • WeatherComparison.cs — historical vs. forecast deltas (WOW)
  • GardenJournal.cs — harvest tracker & journal log (WOW)
  • WeatherDashboard.cs — 7-day visual forecast display
  • GardenVisualizer.cs — ASCII scenic garden with progress bars

Data Source 2: NOAA GHCN Historical Data

HISTORICAL CLIMATE
  • Source: NOAA Global Historical Climatology Network (GHCN-Daily) via AWS S3 public bucket — no key required
  • Station lookup: Downloads 14 MB master station list; applies Haversine distance to find the nearest 10 stations
  • Fallback chain: Tries each of the 10 nearest stations until one has data; falls back to embedded Morgantown normals if all fail
  • Format: CSV with rows of StationID, YYYYMMDD, Element, Value
  • Unit conversion: tenths-of-°C → °F; tenths-of-mm → inches
WHAT WE COMPUTE

Monthly Aggregates (12 months)

  • Average high & low temp (°F)
  • Minimum recorded temp → USDA hardiness zone
  • Total precipitation & frost day count
  • Last spring frost date (Jan–Jun ≤ 32°F)
  • First fall frost date (Aug–Dec ≤ 32°F)
  • Growing season length (days between the two)
USDA Zone is not hardcoded. It is derived live from last year's actual minimum temperature — making plant recommendations accurate for your real local climate.

The Plant Database

23 PLANTS — NO EXTERNAL FILE

Categories

  • 10 Vegetables — Tomato, Cucumber, Pepper, Lettuce, Spinach, Carrot, Kale, Zucchini, Green Beans, Broccoli
  • 5 Herbs — Basil, Mint, Rosemary, Lavender, Chives
  • 4 Flowers — Sunflower, Marigold, Zinnia, Black-Eyed Susan

Per-Plant Data Stored

  • Min USDA zone, temp range (min/max °F), water & sun needs
  • Planting months & harvest months (arrays)
  • Days to harvest; companion plants & plants to avoid
  • Expert planting tip + ASCII art (5–6 lines)

Key Feature: Garden Manager

6 × 10 PLOT GRID
  • 60 individual plots — each stores plant name, date planted, row, column, and notes
  • ASCII grid displays 3-letter codes (TOM, CUC, PEP) or a dot for empty cells
  • State auto-saved to garden_state.json after every change — garden survives between sessions
  • GardenEntry.DaysGrown() tracks exact elapsed days per plot since planting date

User Actions

  • [A] Add — pick from 23 plants, choose row/column
  • [R] Remove — by row/column coordinate
  • [V] View progress — days grown + harvest progress bars
  • [C] Care actions — Water / Cover for frost / Skip, with live weather suggestion
SCENIC GARDEN VIEW

Before the grid manager loads, GardenVisualizer.cs renders a full ASCII art garden scene — each plant type appears with its stored ASCII art, and per-plot progress bars show harvest proximity at a glance.

Persistence design: Two tomatoes planted on different dates show different progress bars. Per-plot tracking uses the exact DatePlanted stored in each GardenEntry — not a shared global counter.

No database required. garden_state.json is written and read directly — a lightweight, portable solution any student can run without setup.

Key Feature: Frost Calculator & Weather Comparison

OPTION 5 — FROST CALCULATOR
  • Finds the last spring frost (latest Jan–Jun date where low ≤ 32°F)
  • Finds the first fall frost (earliest Aug–Dec date where low ≤ 32°F)
  • Calculates growing season length in days and shows where in the season you are today
  • Monthly frost risk table: None / Low / Moderate / High / Very High
  • Real-time alert if the 7-day forecast has any night below 36°F
OPTION 8 — HISTORICAL COMPARISON
  • Compares this week's avg high/low/precip against last year's monthly averages for the same month
  • Per-day deviation: "+4.2°F above normal" or "–1.5°F below normal"
  • Full 12-month historical table with the current month highlighted in gold
  • Auto-generated climate insights: running hot → shade cloth advice; running cold → heat-lover warning
Both features need NOAA historical data. If the NOAA S3 fetch fails or times out, both fall back to embedded Morgantown, WV climate averages — the app stays fully functional and demonstrates the complete feature set without a network connection.

WOW Features

WOW 1

Moon Phase Planting Guide

Calculates the current lunar phase using a 29.53-day synodic cycle. Maps the phase to one of 8 named phases (New, Waxing Crescent … Full … Waning Crescent) and recommends which plants to focus on. Renders a 14-day lunar calendar and ASCII moon art. Based on traditional biodynamic agriculture principles.

WOW 2

Historical vs. Forecast Comparison

Side-by-side comparison of this week's NWS forecast against last year's NOAA monthly averages for the same period. Shows temperature and precipitation deltas per day, a full 12-month climate summary table, and auto-generated gardening insights (shade cloth, heat-lovers, frost risk).

WOW 3

Garden Journal & Harvest Tracker

Tracks days-to-harvest for every plot with live progress bars and harvest urgency alerts. Users can log typed entries — observations, harvest records, pest issues, or general notes — each stamped with date, plot, and type tag. Persisted to garden_journal.txt between sessions.

All three WOW features were built on top of the core classes the group developed across MIST 352 assessments, using Claude Code to accelerate the implementation of complex domain logic (lunar calculations, climate analysis, and file-backed journaling) without changing the underlying data models.

Summary & Key Design Decisions

What Makes This System Work

  • Two NOAA sources answer different questions — forecast tells you what's coming; historical tells you what's normal
  • USDA zone is derived from actual last-year temperature data — not a hardcoded lookup table
  • Plant data is fully embedded — no file dependency, works on any machine instantly
  • Garden state persists to JSON — two sessions, same garden, exact progress per plot
  • All three external services are completely free — no API keys required for any student

Development Model

  • Core data classes & service layer built by the group through iterative MIST 352 assessments
  • Claude Code extended the system with advanced advisory, WOW features, and visual UI layers — without modifying the group's foundational class design
  • Result: a clean separation between what the group designed and what AI built on top
Future enhancements: Multi-year NOAA history for more accurate frost averages; push alerts when frost risk is high; a web-based garden grid replacing the console UI; integration with local soil data from USDA Web Soil Survey.
