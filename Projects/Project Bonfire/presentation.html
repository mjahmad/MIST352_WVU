How This System Was Built

GROUP WORK — Course Assessments

Core Classes — Built by the Team

The group designed and coded the foundational classes of this system throughout MIST 352. These classes form the backbone of the application:

  • Program.cs — application entry point and main menu flow
  • WeatherDay.cs — daily weather model for forecast information
  • NOAAService.cs — weather API integration layer
  • ConsoleUI.cs — reusable console styling, colors, and section headers
  • BonfirePlan.cs — stores the location, date, time, and fire-planning details
  • FireCondition.cs — evaluates whether weather is safe for a fire
  • MenuHandler.cs — organizes user choices and application navigation
  • UserInput.cs — validates menu selections and typed user entries
AI ASSISTED — Advanced Features

Features Built on Top — Using Claude Code / AI Help

AI assistance was used to extend the core class foundation with stronger user experience, cleaner output formatting, and more realistic bonfire decision logic:

  • SeatingAdvisor.cs — recommends seats adjacent to the wind path
  • DrawCompass() — ASCII compass showing wind origin and smoke flow
  • GetOpposite() — calculates where smoke drifts based on wind source
  • GetBestDirection() — safe seating logic based on perpendicular directions
  • DrawSplash() — red and white branded console splash screen
  • PrintCenteredLine() — fixes spacing around emoji-based console text
  • Fire Readiness Summary — combines rain, wind, and comfort conditions
  • Safety Notes — gives practical reminders for real outdoor use

What the App Does

A console-based bonfire planning system that turns weather data into clear outdoor recommendations:

[1]

Weather Dashboard

Displays the forecast for the selected location, including temperature, wind, precipitation, and short conditions.

[2]

Fire Condition Check

Evaluates whether the weather is good for a bonfire based on rain chance, wind strength, and general comfort.

[3]

Seating Advisor

Uses wind direction to recommend where users should sit so they avoid the smoke path.

[4]

Wind Compass

Shows an ASCII compass with North, South, East, West, and a fire marker in the center.

[5]

Smoke Flow Diagram

Draws arrows showing where wind enters and where smoke drifts after passing over the fire.

[6]

Safety Reminders

Provides practical reminders like avoiding high wind, checking rain, and staying out of smoke.

[7] WOW

Realistic Seating Logic

The app does not simply send users to the opposite direction. It recommends sitting adjacent to the wind path.

[8] WOW

Styled Console UI

Uses red and white console styling, clean dividers, centered text, and readable section labels.

[9] WOW

Weather-Based Planning

Brings together forecast conditions and decision logic so the user can plan a better fire night.

Wind and Smoke Logic

WHY THE LOGIC MATTERS
  • Wind direction tells where the wind is coming from, not where the smoke is safe
  • Smoke drifts in the opposite direction of the wind source
  • Sitting directly opposite the wind source puts the user in the smoke path
  • The safest seats are adjacent or perpendicular to the smoke path
  • The compass and arrow diagram make the decision easier to understand visually
EXAMPLE

Wind From North

  • Wind comes from the North
  • Smoke drifts toward the South
  • South is not a good place to sit
  • The best seats are East or West
  • This gives users a real-world recommendation instead of a simple opposite-direction answer
Key fix: GetOpposite() shows where smoke goes, while GetBestDirection() shows where people should sit.

CODE DESIGN

The seating advisor separates two different ideas: where smoke moves and where users should sit. This makes the code easier to explain and prevents the recommendation from placing someone directly in the smoke.

case "N": return "East or West"; case "E": return "North or South"; case "NE": return "Northwest or Southeast";
Design decision: the app prioritizes practical comfort and smoke avoidance, not just raw compass opposites.

User Actions

SPLASH SCREEN DESIGN

The splash screen gives the project a polished first impression while still staying simple enough for a C# console application. The red borders and fire emoji reinforce the bonfire theme immediately.

Spacing design: manually counting spaces is unreliable with emojis, so helper methods create consistent line widths and cleaner output.

Key Feature: Fire Conditions & Recommendations

FIRE READINESS CHECK
  • Checks whether rain is likely enough to make the fire unpleasant or unsafe
  • Uses wind speed to warn when smoke or fire spread may become a concern
  • Uses temperature to help decide whether conditions are comfortable
  • Combines multiple weather fields into a single plain-English recommendation
  • Keeps the output student-friendly and easy to explain during a demo
USER-FRIENDLY OUTPUT
  • Shows wind coming from and smoke drifting to as separate lines
  • Displays a check mark next to the best seating recommendation
  • Uses color to separate warning, fire, good, and dimmed text
  • Avoids technical overload by explaining the result in normal language
Practical value: the user does not have to interpret raw weather data. The app translates the forecast into what they actually need to know before sitting around a fire.

WOW Features

WOW 1

Smoke-Aware Seating

Instead of recommending the opposite side of the wind, the app finds the safest adjacent positions. This makes the feature feel realistic because users are kept out of the smoke path.

WOW 2

ASCII Compass + Flow Diagram

The app displays a compass with the fire in the center and a second smoke flow diagram with directional arrows. This makes wind direction easier to understand in a console-only project.

WOW 3

Polished Fire-Themed UI

The project uses a red and white visual theme, fire emojis, clean section headers, and centered splash screen formatting to make the console feel more like a complete product.

All three WOW features were built on top of the core MIST 352 console application structure, using AI assistance to refine the logic and presentation while keeping the project understandable and demo-ready.

Summary & Key Design Decisions

What Makes This System Work

  • Live weather data makes the recommendations more realistic than hardcoded examples
  • Wind and smoke are treated as separate concepts so the seating logic makes sense
  • The console interface is simple, colorful, and easy to demo
  • The project solves a real comfort problem: avoiding smoke while sitting around a fire
  • The app stays lightweight and portable because everything runs in a C# console project

Development Model

  • Core classes and menu flow were built through the MIST 352 project structure
  • AI assistance helped polish the seating logic, console formatting, and presentation layer
  • Result: a practical planning tool that combines coding concepts with a real-world outdoor scenario
Future enhancements: add local fire-ban alerts, save favorite bonfire locations, include group-size seating suggestions, and show hourly weather changes for the exact fire time.
